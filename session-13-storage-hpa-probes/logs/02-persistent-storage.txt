# 
# student-pv was always bindable - it has no storageClassName, i.e. class "".
# The defect was ONLY on the claim side. A PVC that OMITS storageClassName gets
# the default class; a PVC that sets it to "" asks for an unclassed PV, and the
# control plane then matched it to student-pv on size + access mode.
# So pv-static.yaml was not actually needed - it sits Available, proving the point.
# 
# Rule of thumb:
#   omitted storageClassName  -> default StorageClass -> DYNAMIC provisioning
#   storageClassName: ""      -> no class            -> STATIC binding to an existing PV
#
