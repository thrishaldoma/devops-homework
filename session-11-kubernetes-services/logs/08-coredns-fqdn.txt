$ kubectl exec curl-client -- cat /etc/resolv.conf

# search = suffixes tried for short names; ndots:5 = any name with FEWER than 5
# dots is treated as relative and gets each suffix appended before being tried absolute.
# 
# ===== short name resolves via the search path =====

# 
# ===== the ndots:5 cost for EXTERNAL names =====
# 'api.github.com' has 2 dots (< 5), so it is tried as a relative name first:
#   api.github.com.default.svc.cluster.local  -> NXDOMAIN
#   api.github.com.svc.cluster.local          -> NXDOMAIN
#   api.github.com.cluster.local              -> NXDOMAIN
#   api.github.com                            -> finally answered
$ kubectl exec curl-client -- nslookup api.github.com 2>&1 | head -12
Server:		10.96.0.10
Address:	10.96.0.10:53

Non-authoritative answer:

Non-authoritative answer:
Name:	api.github.com
Address: 20.207.73.85


# The extra lookups are visible directly in the ExternalName test (05-externalname.txt),
# where nslookup printed 4 NXDOMAIN lines before the answer.
# 
# Measuring the cost: 50 lookups of the relative name vs 50 of the absolute name.
$ time -p sh -c 'i=0; while [ $i -lt 50 ]; do nslookup api.github.com  >/dev/null; i=$((i+1)); done'
real 0.02
user 0.01
sys 0.00

$ time -p sh -c 'i=0; while [ $i -lt 50 ]; do nslookup api.github.com. >/dev/null; i=$((i+1)); done'   # trailing dot
real 0.01
user 0.00
sys 0.00

# ~2x slower for the relative form. The absolute numbers are tiny here because
# CoreDNS is one hop away on an idle 2-node lab cluster and caches aggressively.
# PRODUCTION IMPACT: each external call can cost up to 4 wasted DNS round-trips
# before the real one. At scale that adds latency and floods CoreDNS. Standard
# fixes: a trailing dot, a per-pod dnsConfig with ndots:1, or NodeLocal DNSCache.
