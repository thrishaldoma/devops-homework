# an alert goes PENDING first, then FIRING once it has held for its 'for' duration:
$ curl -s 'http://127.0.0.1:19090/api/v1/alerts' | python3 -c "
import sys,json
for a in json.load(sys.stdin)['data']['alerts']:
    print('  %-22s %-8s %s' % (a['labels']['alertname'], a['state'].upper(), a['annotations'].get('description', a['annotations'].get('summary',''))))"
  NodeMemoryHigh         FIRING   192.168.49.3:9100 memory is 39.2%.
  NodeMemoryHigh         FIRING   192.168.49.2:9100 memory is 40.6%.
  PodNotReady            PENDING  Pod argocd/argocd-applicationset-controller-76fd8cdd4f-x54q7 not ready

# The 20% memory threshold is deliberately low so the rule fires on an idle
# lab cluster; production would use >85% for 10m. The PodNotReady and
# PodRestartingTooOften rules are the genuinely useful ones - the second is
# what catches the CrashLoopBackOff from Session 14 before a human notices.

# ===== Grafana, wired to Prometheus as its datasource =====
# The admin password is read from the cluster Secret at run time and passed
# through $GRAFANA_PW - it is never written into this transcript.
$ GRAFANA_PW=$(kubectl get secret -n monitoring grafana -o jsonpath='{.data.admin-password}' | base64 -d)

$ curl -s -u "admin:$GRAFANA_PW" http://127.0.0.1:13000/api/health
